# Generating pipeline models with dbt-pipeline-utils

[dbt-pipeline-utils](https://github.com/carrollaboratory/dbt-pipeline-utils)
- Package used to generate dbt pipeline files. This README covers the ACR
  justfile, [justfile.acr](justfile.acr), which provides reusable command
  configurations for this pipeline.
- Contains custom dbt macros and tests. These are separate and are installed
  through the dbt project's [packages.yml](acr_dbt_pipeline/packages.yml). For
  documentation on these macros and tests visit the repo.

### Which models are generated

The CMG pipeline in [acr_dbt_pipeline/models/cmg](acr_dbt_pipeline/models/cmg)
has these stages:

| Stage | Models | How they are produced |
|---|---|---|
| SRC | `cmg_<site>_src_<consent>_<table>` | Parquet snapshot macros configured in [dbt_project.yml](acr_dbt_pipeline/dbt_project.yml); see the [CMG README](acr_dbt_pipeline/models/cmg/README.md). |
| MAIN | `cmg_main_<table>` | `union_enabled_srcs` macro over the enabled snapshots. |
| INT, `_global_id_map` | `cmg_int_<table>` | Hand-written transformations. |
| **STB** | `cmg_stb_<table>` | **Generated by `justfile.acr`** from the ACR harmonized data model release, then hand-mapped. |

Only STB is generated. The data dictionaries (DDs) come from the
`project-artifacts.zip` asset of
[anvilproject/acr-harmonized-data-model](https://github.com/anvilproject/acr-harmonized-data-model/releases)
(release alias `acr`).

### 1. Set up the tools

Run commands from this repository's root. If using one, create and/or activate
a virtual environment. Install the standalone [Just command runner](https://just.systems/man/en/)
with `cargo install just`, then install the developer-only Python tools:

```bash
python -m pip install \
  "dbt-pipeline-utils @ git+https://github.com/carrollaboratory/dbt-pipeline-utils.git" \
  "sqlfluff>=4.0.0,<5.0"
```

- Troubleshooting:
  - Just installation: If `cargo` is not available, it must be installed first
    as part of the Rust toolchain. See [rustup](https://rustup.rs/) for setup,
    then run `cargo install just`.

```bash
just --version
command -v generate_models_yml generate_sql_models extract_release_artifact_file sqlfluff
```

Generated SQL is fixed and linted with SQLFluff using
[lint/.sqlfluff](lint/.sqlfluff) (DuckDB dialect, Jinja templater, two-space
indentation, lowercase keywords). No database or compiled dbt manifest is
needed. Generated files are checked before they are copied into the output
folder, so a formatting or lint failure does not replace existing model files.

Generation writes files only. **Existing SQL is overwritten**, including the
hand-mapped STB transformations (for example `cmg_stb_subject.sql`). Commit or
back up your work first, and inspect the generated diff before running dbt.
Files for tables removed from a release are not deleted.

[pipeline.just](pipeline.just) contains shared stage orchestration;
[common.just](common.just) contains generator invocations. Keep both beside
`justfile.acr`, and do not copy shared recipes into the profile. Nested calls
retain the selected configuration and command-line overrides.

List the available recipes:

```bash
just -f justfile.acr --list
just -f justfile.acr help
```

### 2. Configure the profile

Edit [justfile.acr](justfile.acr), not the shared recipe files. All settings
can be overridden at runtime with `NAME=value`:

```bash
just -f justfile.acr RELEASE_TAG=v1.5.3 generate-stage stb
```

Settings use direct assignments, so environment variables do not override
them. `RELEASE_TOKEN` is the exception: it reads the environment so credentials
need not be stored in a file or passed as command-line arguments.

| Setting | Default | Purpose |
|---|---|---|
| `PROGRAM_ID` | `acr` | Program name; also the default release repository alias. |
| `STUDY_ID` | `cmg` | Study folder under `MODELS_STAGE_ROOT` and the STB model prefix. |
| `PIPELINE_STAGES` | `stb` | Stages run by `generate-all-stages`. |
| `MODELS_STAGE_ROOT` | `acr_dbt_pipeline/models` | Output folders resolve to `<MODELS_STAGE_ROOT>/<STUDY_ID>/<stage>`. |
| `STB_RELEASE_ASSETS` | `acr\|project-artifacts.zip` | Release DD inputs, as space-separated `repo\|asset` entries. `repo` is an alias (`acr`, `inc`, `kf`, `common`) or a full GitHub repository URL. |
| `RELEASE_ASSETS` | empty | Fallback release list when `STB_RELEASE_ASSETS` is empty. |
| `RELEASE_TAG` | `latest` | Release tag. `latest` follows GitHub's latest release; pin a tag (for example `v1.5.3`) for reproducible output. |
| `RELEASE_TOKEN`, `REFRESH` | env / empty | Optional GitHub token; any nonempty `REFRESH` forces a fresh download. |
| `STB_DD_DIR` | empty | Optional local DD directory, used instead of or together with the release. |
| `STB_STAGE_DIR` | empty | Overrides the default `acr_dbt_pipeline/models/cmg/stb` output folder. |
| `STB_TABLE_PREFIX_STAGE` | `<STUDY_ID>_stb` | Model, SQL filename, and doc ID prefix. Use `none` to disable it. |
| `STB_FROM_CLAUSE_TEMPLATE` | empty | Optional FROM clause; empty generates FROM-less scaffolding. |
| `DD_FORMAT` | `ftd_dd` | DD column mapping. |
| `VERSION_LOG` | empty | Optional DD version/hash log; empty disables it. |

Release inputs are read in memory, so extraction is not required first. If
both `STB_DD_DIR` and a release list are set, both are passed to the
generator. To generate only from local DDs:

```bash
just -f justfile.acr \
  STB_DD_DIR=utils_resources/data_dictionaries/acr \
  STB_RELEASE_ASSETS="" \
  generate-stage stb
```

### 3. Generate STB

```bash
just -f justfile.acr generate-stage stb
# Equivalent while PIPELINE_STAGES is "stb":
just -f justfile.acr generate-all-stages
```

This writes `_models.yml`, `_column_descriptions.md`, and one
`cmg_stb_<table>.sql` per ACR DD into `acr_dbt_pipeline/models/cmg/stb`.
Model YAML column names are normalized to lowercase to match the generated SQL
aliases; for example, `VirtualBiorepository_vbr_id` becomes
`virtualbiorepository_vbr_id`.

Generated SQL is scaffolding that casts each DD column to its type:

```sql
select
  subject_id::text as "subject_id",
  subject_type::text as "subject_type",
  ...
```

By default there is no FROM clause, so models do not reference INT models that
may not exist yet. To select from same-named INT models instead:

```bash
just -f justfile.acr \
  STB_FROM_CLAUSE_TEMPLATE="{{ ref('cmg_int_{base_name}') }}" \
  generate-stage stb
```

`{base_name}` is the table name without the STB prefix; `{table_name}`
includes it and would make a model reference itself. Either way, implement the
INT-to-STB mappings before building the pipeline. Generation alone does not
establish valid transformations.

To regenerate only part of the bundle:

```bash
just -f justfile.acr generate-stage-models-yml stb
just -f justfile.acr generate-stage-model-sql stb
```

To write somewhere other than the model folder, for example to review changes
against the hand-mapped models:

```bash
just -f justfile.acr STB_STAGE_DIR=/tmp/cmg_stb generate-stage stb
diff -r /tmp/cmg_stb acr_dbt_pipeline/models/cmg/stb
```

`clean-dir stb` deletes leftover `*_generated.sql` files from the STB folder.

YAML generators update existing files and docs may append; inspect output when
changing prefixes so obsolete names and docs do not remain. Enabled snapshots,
filters, and Parquet paths are configured separately in
[dbt_project.yml](acr_dbt_pipeline/dbt_project.yml); generation does not
change them.

### Direct generator commands

The direct wrappers take explicit inputs and outputs instead of stage
settings:

```bash
just -f justfile.acr \
  RELEASE_ASSETS="acr|project-artifacts.zip" \
  TABLE_PREFIX=cmg_stb \
  MODELS_YML=/tmp/cmg_stb/_models.yml \
  MODELS_DOCS=/tmp/cmg_stb/_column_descriptions.md \
  generate-models-yml

just -f justfile.acr \
  RELEASE_ASSETS="acr|project-artifacts.zip" \
  TABLE_PREFIX=cmg_stb SQL_DIR=/tmp/cmg_stb \
  generate-model-sql
```

Direct commands share `DD_DIR`, `RELEASE_ASSETS`, `DD_FORMAT`, `TABLE_PREFIX`,
`FROM_CLAUSE_TEMPLATE`, and the release settings.

### Optional: download release files

This is separate from generation. It extracts the ACR model's DDs and upstream
dbt files for reference:

```bash
just -f justfile.acr refresh-releases
```

| Setting | Default |
|---|---|
| `REFRESH_BUNDLES` | `program` (the ACR model only; there is no common bundle for this pipeline) |
| `PROGRAM_RELEASE_REPO` | `PROGRAM_ID` (`acr`); a full GitHub repository URL also works. |
| `RELEASE_ARTIFACT` | `project-artifacts.zip` |
| `DD_INTERNAL_PATH` | `project/data-dictionary` |
| `DBT_INTERNAL_PATH` | `project/dbt` |
| `PROGRAM_REFRESH_DIR` | `utils_resources/data_dictionaries/acr` |

DDs are extracted to `PROGRAM_REFRESH_DIR` and upstream dbt files to its
`dbt/` subdirectory. These are reference files, not a replacement for this
project's model folders. `RELEASE_TAG`, `RELEASE_TOKEN`, and `REFRESH` apply.

For a single archive path, use `extract-release-file`:

```bash
just -f justfile.acr \
  RELEASE_INTERNAL_PATH=project/data-dictionary \
  RELEASE_OUTPUT_PATH=/tmp/acr-release-dd \
  extract-release-file
```

`RELEASE_REPO` defaults to `PROGRAM_RELEASE_REPO`. Both the internal and output
paths are required.
